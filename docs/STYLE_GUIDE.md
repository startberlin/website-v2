| [LumaEvents](../src/components/LumaEvents.astro) | Reusable section with START Berlin's public Luma calendar, used on Events and ready for Home or Join. Props: required `id` (the heading gets `${id}-heading`) and `heading`, optional `level`, `eyebrow`, `lead` and `layout`. The default layout is a standalone section. Events sets `layout="panel"` for the compact embed above the members' section. The embed URL, Luma links, frame title and status text come only from `lumaCalendar` in [luma.ts](../src/lib/luma.ts). "View calendar on Luma" sits above the frame in the server HTML and opens a new tab with `rel="noopener noreferrer"`. The frame reserves `clamp(24rem, 80svh, 56rem)` because Luma never reports its height. The panel uses `clamp(22rem, 46svh, 28rem)` and selects the dark appearance using the Luma embed URL. Plain status text behind the transparent frame shows while it loads and stays if Luma is blocked; JavaScript cannot detect a failed embed. The frame is lazy and has no `allow` or `referrerpolicy` attribute, so the site's `no-referrer` applies. The sandbox allows scripts, same-origin, forms, popups and popups-to-escape-sandbox. Luma needs scripts and its own origin: with an opaque origin its requests fail silently and it looks like an empty calendar. Forms and popups are for guest registration and Luma sign-in; confirm or remove them once registration is tested with a listed event. The current CSP has no `frame-src`; one added later must include `https://luma.com`. A future `Cross-Origin-Opener-Policy: same-origin` needs a registration re-test. Browsers never match `:focus` on an iframe whose content has focus, so a small script adds `is-focused` to the frame wrapper when Tab moves focus into it, for the shared focus outline. It only toggles that class: no `innerHTML`, storage, `postMessage` or network requests. Without JavaScript the frame and link still work. Luma's embed lists upcoming events only and ignores `period=past`, so pages link past events instead. |

## Page heroes

Start each HTML page with PageHero, including profiles, job details, legal pages and errors. The image fills the width and the copy aligns with the shared page container. Home supplies its existing slideshow through the `background` slot and keeps the viewport-height layout. Supporting copy and controls use the `status`, `description`, `actions` or `aside` slots.

Write the H1 as two short parts in a single `title` pair. The first part is solid white and the second is a START cyan outline. Member Journey uses `accentFirst` for solid cyan "Your START Berlin" and white outlined "Journey". Forced-colors mode fills the outline with the system text color. Long names and job titles can use `compactTitle`. Both parts may wrap on narrow screens or with enlarged text. Job details use the role and employer as the two title parts.

Keep the optional description to one short sentence. Omit it when the title carries the introduction, as on Member Journey. Events, About Us and Partners use the standard two-line PageHero and put their opening copy in [PageIntroduction](../src/components/PageIntroduction.astro) below the photo. It uses the shared page inset and reading width. Keep job locations and work mode in the listing hero so readers can identify the role at a glance.

On screens below 640 px, the Home title uses the larger mobile landing scale. Other page heroes keep the shared title scale.

Choose an approved START Berlin photo that fits the page subject. Member Journey uses `start-berlin-member-journey-group.jpg`. Board profiles reuse the Members team photo. Jobboard pages reuse the company-visit photo. Legal pages reuse the event audience photo. The 404 page uses `hero-404.jpg` as a decorative team photo. Optimize new sources locally and strip embedded metadata. Use empty alt text for decorative reuse and meaningful alt text where the image conveys relevant information.

The 404 hero uses the standard PageHero title size and offers Home and Jobs as primary destinations. A short recovery tip leads to a navigation group with SectionHeading and the shared text actions for Events, Our Members, Member Journey and Apply Now. The shared footer follows the recovery navigation.

Set `imagePosition` and `mobileImagePosition` to keep the subject visible at both crops. Astro serves responsive WebP sizes up to the source width, and prioritizes the first visible photo. Shared gradients keep the title and copy readable. On phones the shade sits behind the copy while the photo stays visible above it. Check the actual crops and contrast at the verification widths, especially for long descriptions and enlarged text.

## UX and accessibility

- Use links for navigation and buttons for actions. Label fields and icon-only controls.
- New touch controls need 44 × 44 px. Shared focus is 2 px Cyan with a 4-px offset.
- Preserve input on errors. Connect hints/errors to fields; show success only after API confirmation.
- Define loading, empty and failure states. Preserve Jobs URL filters and pagination through reload/Back.
- Use equal vertical spacing between the Jobs empty-state content and its two dividers.
- Follow the system's reduced-motion setting, including changes made while a page is open. List transition properties explicitly.
- Use local Astro image assets, reserved dimensions and meaningful alt text. Check photo crops and overlay contrast.
- Meet [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/). Verify keyboard access, visible/unobscured focus and screen-reader names, states and announcements. Check 200% text zoom and reflow at 320 px.

## Verification

Every component must look correct and remain accessible across device sizes. Test all affected components in their relevant default, focused, open, loading, empty, error, success and disabled states.

| Device | Minimum test widths (CSS px) |
| --- | --- |
| Smartphone | 320, 390 |
| Tablet | 768, 1024 |
| Desktop | 1280, 1440, 1920 |

Check portrait and landscape on phones/tablets. Resize between sample widths and test both sides of affected breakpoints. At every size, verify matching left/right content edges across routes, readable text and usable controls without clipping, overlap or horizontal page overflow. Check image crops.

Run `check:design` and the checks in [AGENTS.md](../AGENTS.md). Combine automated checks with manual visual, keyboard and screen-reader checks. Fix failures before completion and record the tested widths, states and results.

Before release, check the Avenir fallback across platforms and verify spoken output with a screen reader.

Job rows reserve a 48 px square beside each company, with a 32 px favicon or fallback icon. Public role titles omit a recognised trailing gender annotation. Employer records and canonical job links preserve the original title and slug. When Cockpit supplies a company favicon for the published role, the website serves it from its own origin. The shared company icon fills the same space while the image loads or is unavailable.
